# 基于脱敏样本的效果验证报告

> 项目：信盾 TrustShield ｜ 验证日期：2026-08-03 ｜ 数据级别：虚构、脱敏演练数据

## 1. 验证目的与范围

本报告验证以下能力是否可在本机源码环境中复现：

1. 脱敏样本中的敏感实体可被替换为任务级唯一占位符，并可按映射完整还原；
2. 信审先行、合同后审的边界是否能对越界条款形成不可绕过的阻断；
3. 信审 Agent 是否仅接受可验证 Claim，并在关键材料或模型能力不满足时失败关闭；
4. 翻译链路是否拒绝在缺少脱敏映射时外发原文；
5. 本机服务与当前已配置的主模型、智能脱敏服务是否可连通。

本次没有使用真实客户、真实合同、真实账号或真实密钥。样本中的客户、联系人、手机号、邮箱、账户、地址、金额和图号均为测试文本。报告不将连接成功等同于真实生产数据的合规授权；生产使用仍须按企业数据治理要求配置网络、存储和模型服务。

## 2. 验证环境与方法

| 项目 | 实际验证条件 |
| --- | --- |
| 操作系统与运行方式 | Windows 本机；已有 FastAPI 服务运行于 `127.0.0.1:8000` |
| 鉴权与安全运行条件 | 管理员登录接口成功；健康接口返回 `llm_configured=true`、`secure_runtime=true` |
| 运行配置状态 | 主模型与智能脱敏服务均已配置；脱敏开关、智能脱敏开关均开启 |
| 连通性方式 | 以管理员令牌调用 `/api/admin/settings/test`，不读取或打印密钥 |
| 功能回归方式 | 从 `backend/` 执行独立 Python 回归脚本 |
| 脱敏样本 | 三条虚构条款，覆盖公司、姓名、电话、金额、银行卡号、邮箱、地址与图号 |

执行命令如下：

```powershell
cd backend
python scripts/test_mask_fast_path.py
python scripts/test_credit_contract_guard.py
python scripts/test_credit_react_agent.py
python scripts/test_translation_privacy.py
```

模型连接测试由已登录管理员在本机调用设置接口完成；模型地址、模型名和 API Key 均保留在受限运行配置中，未写入仓库或本报告。

## 3. 实测结果

### 3.1 当前运行配置连通性

| 检查项 | 结果 | 实测值 |
| --- | --- | --- |
| 管理员认证 | 通过 | `LIVE_API_AUTH=PASS` |
| 安全运行条件 | 通过 | `secure_runtime=true` |
| 主模型配置 | 已配置且连通 | 连接测试成功，约 **957 ms** |
| 智能脱敏服务配置 | 已配置且连通 | 连接测试成功，约 **849 ms** |
| 脱敏/智能脱敏开关 | 已启用 | `enable_masking=true`，`smart_mask=true` |

该连通性检查只发送“Reply with OK only.”一类最小测试请求，证明当前配置可被系统调用；它不携带合同、财报或任何生产原文。

### 3.2 脱敏样本结果

| 样本覆盖 | 检查结果 |
| --- | --- |
| 公司与联系人 | 已替换为 `<MASK-COMPANY-*>`、`<MASK-PERSON-*>` 类占位符 |
| 电话、邮箱、银行卡号、地址 | 已替换为对应类别占位符 |
| 金额与技术图号 | 已替换为 `<MASK-AMOUNT-*>`、`<MASK-TECH-*>` 类占位符 |
| 任务级唯一性 | 通过：不同条款不会复用同一占位符导致错误还原 |
| 可逆性 | 通过：脱敏文本按映射还原后与原样本文本逐字一致 |
| 实测统计 | **9 个敏感实体**，脚本运行耗时 **0.27 ms** |

本项脚本的输出为：`fast masking checks passed: 9 entities, 0.27 ms, reversible task-wide mapping`。该脚本验证的是本地确定性快速脱敏与映射逻辑；智能脱敏服务本身已按 3.1 的运行配置接口完成连通性测试。两者共同构成“规则覆盖高频实体、智能识别补足残余实体”的分层机制。

### 3.3 自主信审与跨流程门禁结果

| 验证项 | 结果 | 说明 |
| --- | --- | --- |
| ReAct 证据循环 | 通过 | Agent 必须通过检索、上下文读取和 Claim 校验形成可用事实 |
| 无配置/材料不足 | 通过 | 返回失败关闭，不产生伪造事实或可直接采用的授信建议 |
| 重复工具调用 | 通过 | 被识别并抑制，避免无效远程调用 |
| 证据完整性 | 通过 | 页/表上下文、主体、期间、币种、单位不满足时 Claim 被拒绝 |
| 信审前置 | 通过 | 合同案件必须绑定已生效信审版本 |
| 合同端越界处置 | 通过 | `CREDIT_TERM`、`CREDIT_PREPAYMENT`、`CREDIT_PAYMENT_METHOD`、`CREDIT_DELIVERY_MODE` 不允许忽略放行 |
| 否定条款理解 | 通过 | “不采用 VMI/JIT”不被误判为采用 VMI/JIT |
| 旧信审版本 | 通过 | 新信用版本生效后，旧版本绑定不得用于导出 |

对应脚本输出：

```text
OK: credit-first contract guard checks passed
production ReAct audit fails closed and accepts only verified Claims
```

### 3.4 翻译隐私门禁结果

翻译链路回归已通过。其验证目标是：当脱敏映射不存在或不完整时，翻译请求被阻断而不是携带原文继续执行；当映射完整时，后续处理仍可按授权链路进行。脚本输出：`translation privacy checks passed`。

## 4. 启明智造脱敏演练场景的效果验证

仓库内的 [启明智造场景材料包](../03-演示与交付/模拟测试材料-v2-启明智造场景/README.md) 提供从信审到合同 V3 的可操作演练。该材料全部为虚构、脱敏数据，建议按以下路径展示业务效果：

| 阶段 | 样本事实 | 应验证的控制效果 |
| --- | --- | --- |

完整操作、预期状态与证据位置见材料包中的 [全流程演示操作手册](../03-演示与交付/模拟测试材料-v2-启明智造场景/10-全流程演示操作手册与人话口播.md) 和 [预期结果与验收清单](../03-演示与交付/模拟测试材料-v2-启明智造场景/07-预期结果与验收清单.md)。

## 5. 结论与限制

本次本机验证证明：当前服务可认证且安全运行配置完备；当前已配置的主模型与智能脱敏服务可连通；脱敏映射满足样本级唯一、可逆要求；信审—合同强绑定、Agent 证据核验失败关闭及翻译隐私门禁的关键回归均通过。

验证结论适用于本仓库版本及上述虚构样本。投产前应补充企业内网环境压测、真实制度规则校准、数据分级授权评审、账号与备份演练，以及由业务、法务和财务共同完成的验收签字。
