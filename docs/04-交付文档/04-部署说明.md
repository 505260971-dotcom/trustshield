# 部署说明

> 项目：信盾 TrustShield ｜ 适用版本：当前仓库源码 ｜ 更新日期：2026-08-03

## 1. 部署形态

| 场景 | 推荐方式 | 访问方式 |
| --- | --- | --- |
| 本地开发/演示 | `python dev.py` 同时启动 FastAPI 与 Vite | 前端 `http://127.0.0.1:5173` |
| 单机生产预览 | 构建前端后，以 FastAPI 托管 `frontend/dist` | `http://127.0.0.1:8000` |
| 企业内网生产 | FastAPI 单服务 + 反向代理 + 受限数据目录 + 企业统一认证/网络策略 | 企业域名 HTTPS 入口 |

当前代码使用 SQLite 保存应用数据；对于单实例、演示和小规模内网使用，可将数据目录挂载到受控持久化磁盘。多实例、高并发或企业级容灾场景应在实施阶段评估共享数据库、对象存储、集中日志和备份策略。

### Docker 单机部署（推荐）

仓库根目录已经提供 `Dockerfile` 与 `compose.yml`。镜像在构建阶段打包前端产物，运行时由 FastAPI 以同一源提供页面和 `/api`，仅需暴露一个端口；同时内置 Tesseract 中文/英文 OCR。

```bash
git clone https://github.com/chengtx007/trustshield.git
cd trustshield
cp backend/.env.example backend/.env
# 编辑 backend/.env，填写 AUTH_SECRET、DATA_ENCRYPTION_KEY 和初始管理员密码
docker compose up -d --build
docker compose ps
```

默认访问地址是 `http://服务器地址:8000`。如需改用其他宿主机端口，在启动前设置 `TRUSTSHIELD_PORT`，例如 `TRUSTSHIELD_PORT=8080 docker compose up -d --build`。应用数据（SQLite、上传原文、导出文件和模型运行配置）存入 Docker 命名卷 `trustshield-data`，镜像升级或重建容器时不会丢失。

常用运维命令：

```bash
docker compose logs -f --tail=100
docker compose pull  # 仅当 compose 改为使用远程镜像时需要
git pull && docker compose up -d --build
docker compose down  # 不会删除 trustshield-data
```

不要执行 `docker compose down -v`，除非已完成备份并明确需要删除全部业务数据。生产环境建议将 8000 端口限制在防火墙或反向代理后，并由 Nginx/Caddy 提供 HTTPS。

## 2. 前置条件

- Python 3.11 或更高版本；
- Node.js LTS 与 npm；
- 可选：Tesseract OCR 及中文、英文语言包（仅扫描版 PDF/图片上传需要）；
- 受限的文件系统目录，用于应用数据库、上传原文、解析资产、脱敏映射和导出文档；
- 由管理员维护的模型服务运行配置。生产环境应连接企业批准的本地或内网模型/检索服务，并遵从数据出域策略。

## 3. 首次部署

### 3.1 获取代码并创建运行参数

```powershell
git clone https://github.com/chengtx007/trustshield.git
cd trustshield
Copy-Item backend\.env.example backend\.env
```

编辑 `backend/.env`，至少配置：

```dotenv
AUTH_SECRET=替换为随机长字符串
DATA_ENCRYPTION_KEY=替换为Fernet密钥
INITIAL_ADMIN_USERNAME=admin
INITIAL_ADMIN_PASSWORD=替换为强密码
INITIAL_ADMIN_NAME=系统管理员
```

生成 Fernet 密钥：

```powershell
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

`backend/.env` 仅用于启动级安全参数，不应提交版本库。模型地址、模型名和 API Key 在首次登录后通过“系统与集成”页面配置，系统仅展示密钥是否已配置。

### 3.2 安装依赖

```powershell
cd backend
python -m pip install -r requirements.txt
cd ..\frontend
npm install
cd ..
```

扫描件 OCR 可选配置：安装 Tesseract 后，在 `backend/.env` 写入 `TESSERACT_CMD`，例如：

```dotenv
TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe
CONTRACTGUARD_OCR_LANGUAGES=chi_sim+eng
```

## 4. 启动与连通性检查

### 4.1 开发/演示模式

```powershell
python dev.py
```

常用变体：

```powershell
python dev.py --no-browser
python dev.py --port 5174 --backend-port 8001
```

启动后登录系统，进入“系统与集成”完成主模型、财报 Agent、智能脱敏、重排和 Embedding 的按需配置。使用管理员页面的“连接测试”检查服务可用性，再使用启明智造脱敏材料完成现场演示。

### 4.2 单服务生产预览

```powershell
cd frontend
npm run build
cd ..\backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

前端构建产物存在时，后端会托管 `frontend/dist`。访问 `http://服务器地址:8000` 即可，不必另行启动 Vite。

## 5. 企业内网部署建议

1. 将代码与运行数据分离：代码目录只读部署；设置 `CONTRACTGUARD_DATA_DIR` 指向受限、持久化的数据目录。
2. 使用 Windows 服务、systemd、Supervisor 或企业容器平台守护 `uvicorn` 进程，启用故障自动重启和标准输出采集。
3. 在 Nginx、IIS 或企业网关终止 TLS，反向代理至应用端口；将 `CORS_ORIGINS` 限定为真实前端域名。
4. 通过企业防火墙/网络策略限制应用到模型、翻译、Embedding、重排服务的网络访问；敏感财务证据的出域开关默认关闭，只有授权后启用。
5. 按最小权限为应用运行账户授予数据目录读写权限，禁止其他普通账户读取 `backend/data/` 或实际数据目录。
6. 上线前替换初始管理员密码；后续账号由管理员界面创建和停用，不共享管理员账号。

示例 Nginx 反向代理（按实际域名、证书和网络策略调整）：

```nginx
server {
    listen 443 ssl;
    server_name trustshield.example.internal;

    ssl_certificate     /etc/nginx/certs/trustshield.crt;
    ssl_certificate_key /etc/nginx/certs/trustshield.key;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 6. 数据备份与恢复

需纳入备份策略的数据包括：

- 应用数据库 `contractguard.db`；
- 运行配置 `config.json`（按企业密钥管理政策加密备份）；
- 上传原文、解析文本资产与已导出文档；
- `.env` 中的启动密钥（应使用企业密钥库或离线保管，不能与普通备份同权限存放）。

建议在低峰期暂停写入或使用一致性快照后备份数据目录，并定期在隔离环境执行恢复演练。恢复时必须同时恢复数据库、映射资产与相应密钥；只恢复数据库而丢失加密密钥会导致历史敏感字段不可解密。
