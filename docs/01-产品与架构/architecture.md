## 合同评审架构（案件中心版）

```text
客户信用档案 / CRM 端口
          │
          ▼
业务申请人发起信审 -> 信用审核专员评估并送审 -> 财务审批主管复核 -> 集团财务总监最终批核 -> 已生效商业边界
          │                                           （账期、预付款、额度、付款方式、交付模式）
          ▼
合同案件（唯一业务对象）
  ├─ 申请信息：客户、业务类型、紧急度、期望完成时间
  ├─ 文件包：主合同、订单、补充协议、附件、修订版本、翻译版本
  ├─ 协同待办：信用审核专员复核、业务补件、分级例外审批
  └─ 事件时间线：提交、审查、处置、审批、导出、归档
          │
          ▼
业务人员上传文件包并绑定该客户已生效的信审版本
          │
          ▼
文档解析 Agent -> 条款编号、页码和原文片段（图片走可选 OCR）
          │
          ▼
脱敏专用 Agent -> 敏感信息映射仅保存在本机
          │
          ▼
字段抽取 Agent -> 主体、业务类型、付款节点、有效期、金额
          │
          ▼
规则候选 Agent -> 词法门控 + 业务类型过滤（16 条封闭底限；不做 per-clause 向量 RAG）
          │
          ▼
语义研判 Agent -> 主体、条件、否定、例外和义务识别（高优先级条款优先，窗口动态）
          │
          ▼
规则引擎 Agent -> 合同底限（确定性全量）+ 信审快照越界校验
          │
          ▼
汇总结论 Agent -> 风险等级、证据、建议和待人工确认
          │
          ▼
受控案件工作流 -> AI 审查中 -> 信用审核专员复核 -> 补件/例外审批 -> 可签约 -> 归档
          │
          ▼
角色工作台 -> 仅展示当前用户需要处理的案件待办；案件中心支持版本对比、翻译持久化和文件切换
          │
          ▼
导出 revised / plain / bilingual
```

## 安全边界

- 合同原文先在本机完成正则脱敏；智能脱敏专用模型在正式部署时使用本地/内网模型，演示环境可使用远端替代模型。远程主合同审查模型只接收脱敏文本。
- 财报由“检索证据块 → 结构化抽取”Agent 处理：生产环境应将该 Agent 指向本地/内网模型；演示环境可明确配置为远端替代。远端替代模式会接收与财务事实直接相关、带页码锚点的原始证据块，不能宣称为脱敏传输。
- 脱敏映射、审查报告、翻译结果和人工处置记录使用 Fernet 加密保存。
- 案件负责人、优先级、截止时间、流程状态和处置动作分开持久化，操作写入审计日志。
- 状态不是自由编辑字段：只能通过领取、退回补件、提交例外审批、确认可签约、审批通过和归档等动作推进；进入可签约前会检查未完成的补件与审批待办。
- 历史的一文件一任务数据会在启动时自动映射为案件下的首个文件版本，旧链接和旧审查结果保持可访问。
- DOCX 导出只包含已人工采纳、编辑后采纳或审批通过的风险项（plain 除外）。
- 信审条件是唯一的商业条件来源。系统同时校验合同交易相对方与所选信审客户一致；任何 `CREDIT_*` 越界不能在合同端采纳、忽略或审批，必须先新建并生效新的信审版本，再重新发起合同复审。
- 16 条销售合同底限为封闭规则集：规则路由使用确定性词法门控，不依赖向量检索。

## 信审自主审计 Agent（受约束）

生产信审不再把所有文件套入固定字段正则后直接评分。运行中的 ReAct Agent 先读取受限材料画像（文件类型、来源锚点、文字/表格/OCR 状态和片段），再根据本案的已见证据自主决定下一次只读工具调用，例如核验主体、财务期间、合并口径、收入/现金流或交易敞口；材料不足时请求补件，而不是猜测或套样例。

```text
材料画像 → ReAct Agent（Reason）→ 只读证据工具（Act）
                                  ├→ 词法候选 + 可选 Embedding 语义召回（RRF 融合）
                                  ├→ qwen3-rerank 候选精排 → 页/表上下文读取
                                  ├→ 敞口快照、已验证 Claim 与冲突比较
                                  └→ 多轮提交 Claim / 请求补件 / 结束
        → 事实/来源/单位/币种/期间/时效的确定性校验
        → 仅完整 verified Claims 进入版本化评分卡与人工审批
```

- Agent 只有受控的只读工具：材料画像、检索、证据/页/表上下文、只读敞口、已验证 Claim 和 Claim 比较；它没有评分、额度、账期、例外、审批或写入工具。
- 每个 Agent 事实必须携带来源块、连续原文引文、原始数值、币种和单位；引文或数值不在来源中即拒绝采用，并保存文件哈希、解析器版本、页/表/行列元数据（若解析器提供）。
- 百炼 Embedding 是可选的请求内语义召回阶段：仅在管理员配置模型、密钥并显式授权财务证据传输后启用；它与受控词法候选以 RRF 融合，不保存向量到业务事实表，也不产生评分或结论。Embedding 已启用但不可用时，生产 ReAct 路径以 `execution_failed` 失败关闭；未启用时保留受控词法候选召回。
- `qwen3-rerank` 仅用于候选证据的请求内精排，不用于抽取或裁决。业务 API 只有生产 ReAct 路径：必须显式授权财务数据传输并配置 qwen3-rerank；服务未配置或失败即 `execution_failed`，不会把词法或向量结果当作已核验证据。旧解析工具仅供 coding agent/CI 的离线调试，不存在可由业务 API 选中的另一套授信运行模式。
- Agent 判断为证据冲突或必需 Claim 不足时，系统返回 `not_assessable`；模型、重排或解析链路失败返回 `execution_failed`。两种状态均阻断“应用建议到草稿”，并输出待补/待人工核验项。

## 角色

| 角色 | 工作范围 |
| --- | --- |
| 业务申请人 | 发起信审和合同申请、上传文件包/修订版、处理本人补件并查看本人案件 |
| 信用审核专员 | 评估、维护并提交客户信审版本；领取合同案件、复核 AI 结论、退回补件或提交例外审批；无最终审批权限 |
| 财务审批主管 | 对信审建议作中层复核；处理主管级合同例外 |
| 集团财务总监 / 最终审批人 | 对已通过主管复核的信审作最终批核；处理重大合同例外，并保留成员、规则、配置和全量审计权限 |
