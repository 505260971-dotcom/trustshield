# 实跑前清理与协作规则

> 适用范围：本文件只针对本机 ContractGuard 的**演练数据库、上传件、导出件与浏览器会话**。它不删除代码、`docs` 材料包、OCR 语言包、模型/规则初始化逻辑或任何真实外部系统数据。

## 1. 先确认，而不是假定数据库为空

本文件不再假定某台机器已经完成过重置。运行记录是否存在，取决于当前机器；每次演练前都应先检查，再由操作人决定继续使用、备份，或按第 2 节重置。

在仓库根目录执行以下**只读检查**：

```powershell
Get-ChildItem -Force .\backend\data
Get-ChildItem -Force .\backend\data\uploads
```

若看到 `contractguard.db`，表示本地至少初始化过数据库；若 `uploads/` 下有文件，表示可能已有上传件或导出件。登录后还应在“客户信审”“合同案件”“组织与规则 → 审计日志”中检查是否已有演练记录。不要仅凭文件夹是否为空判断业务记录是否为空。

第一次启动（或按第 2 节重置）后，应用会自动创建空数据库并初始化规则目录、信用模型、审批路由和初始管理员。这些是系统运行所需的种子配置，并不是历史演练数据。

## 2. 日后重置的精确范围

必须先停止本地后端服务，再执行重置；重置会不可逆地删除本机演练账号、案件、审计和上传/导出件。只允许清理下列可再生目标：

| 目标 | 处理 | 原因 |
| --- | --- | --- |
| `backend/data/contractguard.db` | 删除（如存在） | 保存本地用户、信审、合同、审批、审计等演练记录的 SQLite 数据库。 |
| `backend/data/contractguard.db-wal`、`backend/data/contractguard.db-shm` | 删除（如存在） | SQLite 的伴随日志文件。 |
| `backend/data/uploads/` 下的内容 | 删除内容、保留目录 | 保存上传的材料、合同和导出文件。 |
| 浏览器的 ContractGuard 站点数据 | 清除 `cg_token` 或执行退出登录 | 避免旧会话令牌残留在浏览器本地存储。 |

绝不能删除 `backend/data/tessdata/`：其中是 OCR 语言包，不包含业务记录。也不要删除 `docs/03-演示与交付/模拟测试材料/`，它是演练素材库而不是应用运行数据。

确认需要从空库开始时，可在**仓库根目录**执行下列精确命令。命令只删除上表列出的运行目标，保留 `config.json` 与 OCR 语言包；如需连模型配置一起重新设置，请先另行备份或由管理员在页面中处理。

```powershell
Remove-Item -LiteralPath .\backend\data\contractguard.db -Force -ErrorAction SilentlyContinue
Remove-Item -LiteralPath .\backend\data\contractguard.db-wal -Force -ErrorAction SilentlyContinue
Remove-Item -LiteralPath .\backend\data\contractguard.db-shm -Force -ErrorAction SilentlyContinue
Get-ChildItem -LiteralPath .\backend\data\uploads -Force | Remove-Item -Recurse -Force
```

## 3. 操作人和 Agent 的分工

| 类型 | 操作人 | Agent |
| --- | --- | --- |
| 启动、登录、定位菜单、读取材料、解释字段、核对结果 | 可操作 | 得到指令后可协助 |
| 创建用户、创建信审、上传文件、保存敞口、运行评估 | 必须逐项确认 | 不自行执行 |
| 送主管、主管复核、最终批核、合同提交、风险处置、导出 | 必须逐项确认，且应由相应角色完成 | 不自行执行或替代判断 |
| 修改信审边界、创建 V2、接入外部 CRM/OA/LLM 服务 | 明确授权后决定 | 仅在明确授权范围内协助 |

“真实跑一遍”指使用真实的本地应用和真实状态机完成每一步，并保留系统实际生成的证据；不等于由 Agent 预先生成案例、审批结果或导出件。每次只推进当前一步，操作人确认页面结果后再继续下一步。

## 4. 从空库开始的第一步

重启应用后，以初始管理员登录，先建立 `reviewer`、`director`（需要业务发起时再建立 `business`）三个本地演练角色。随后优先打开 [10-从零实跑操作说明.md](./10-从零实跑操作说明.md)，按其中的“启动前检查”和“停点 A”确认环境、角色与数据状态，再创建第一条信审草稿；[08-完整演练操作手册.md](./08-完整演练操作手册.md) 可作为精简演示脚本和验收材料对照。
