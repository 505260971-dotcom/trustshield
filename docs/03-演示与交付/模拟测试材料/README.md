# ContractGuard 模拟测试材料包

> 版本：v1.0 ｜ 场景日期：2026-07-28 ｜ 数据属性：**全部为虚构、脱敏的演练数据**。

本材料用于在 ContractGuard 中完整演练“客户信审 → 授信生效 → 合同评审 → 信审阻断 → 合同修订复审 → 导出”的闭环。不要将本目录内容作为真实授信结论、法律意见或对外合同使用。

## 文件清单与用途

| 文件 | 在流程中的用途 |
| --- | --- |
| `00-实跑前清理与协作规则.md` | 清空本地演练记录、创建角色账户，以及“由操作人确认、Agent 仅陪跑”的执行边界。每次从空库开始前先读此文件。 |
| `01-信审申请单.md` | 新建客户信审版本时填写的客户、申请条件、申请理由和人工复核依据。 |
| `02-客户财务报告-模拟.txt` | 在“客户信审 → 材料与交易敞口”上传为“财务报告”；包含评分所需的 7 项核心财务事实。 |
| `02-客户财务报告-模拟.docx` | 与 `.txt` 内容相同的 Word 版，方便现场查看或演示上传 Office 文档；单次信审只上传其中一个版本，推荐优先使用 `.txt` 以获得稳定的文本解析结果。 |
| `03-CRM-ERP敞口快照-模拟.json` | 将其中数值手工填写到 CRM/ERP 敞口快照表单；不是直接上传文件。 |
| `04-风险合同-待审.docx` | 绑定授信版本后首次上传；故意同时触发合同底线风险和 `CREDIT_*` 信审越界。 |
| `05-例外审批说明-模拟.md` | 在合同审查后作为“补件/审批说明”参考；仅处理合同底线例外，不能放宽信审边界。 |
| `06-修订后合同-复审.docx` | 在信审版本仍有效且条件未变时提交复审；用于验证信审越界消除和可签约闭环。 |
| `07-预期结果与验收清单.md` | 每一步应看到的状态、风险及验收证据。 |
| `08-完整演练操作手册.md` | 面向操作人的逐步走查脚本、角色分工与异常分支。 |
| `09-完整演练操作手册（Word版）.docx` | 现场演示或交付使用的 Word 版脚本；首次实跑时以 10 的当前页面路径、角色权限和异常分支为准。 |
| `10-从零实跑操作说明.md` | **推荐从这里开始**：按当前页面、角色权限和状态机编写的完整实操说明，含安装、启动、空库检查、正常/模型异常分支、合同复审和验收证据。 |

## 推荐角色

| 演练角色 | 系统角色 | 负责动作 |
| --- | --- | --- |
| 信用审核专员 | `reviewer` | 新建信审、上传材料/敞口、运行评估、确认或修订建议、送主管复核。 |
| 财务审批主管 | `director` | 审批信审 V1；对合同中的 R16（VMI/JIT）例外审批。 |
| 集团财务总监 | `admin` | 最终批核信审 V1；对 R03/R04/R05 的合同例外审批。 |
| 业务经办人 | `business`（可选） | 发起合同评审、跟踪补件与采纳修改建议。 |

> 从空库开始时，系统仅自动初始化管理员。请先由管理员创建 `reviewer`、`director`（以及需要时的 `business`）角色账户；不把实际账号、密码或令牌写入本材料包。

## 实跑协作边界

演练由操作人主导。Agent 可以在得到明确指令后启动本地服务、定位页面、解释字段和核对预期结果，但不得自行创建信审、上传材料、送审、批准、修改合同、导出或绕过任何阻断。每一个会改变业务状态的动作都应在操作人确认后单独执行；详细的重置范围和停点见 [00-实跑前清理与协作规则.md](./00-实跑前清理与协作规则.md)。

## 预期闭环（先失败，再修复）

```text
信审材料 + 敞口快照
        ↓
量化评估 / 审核专员留痕 / 两级审批
        ↓
已生效信审 V1（合同唯一可绑定的商业边界）
        ↓
上传 04 风险合同
        ↓
合同底线风险 + CREDIT_* 信审阻断
        ↓
仅修改合同可改的条款；信审越界不得在合同端审批放行
        ↓
上传 06 修订合同复审
        ↓
无 CREDIT_* → 处理必要的合同风险/审批 → 导出建议稿
```

第一次实跑请使用 [10-从零实跑操作说明.md](./10-从零实跑操作说明.md)。完整点击路径、预期输出和失败分支亦见 [08-完整演练操作手册.md](./08-完整演练操作手册.md)；需要 Word 格式时，使用 [09-完整演练操作手册（Word版）.docx](./09-完整演练操作手册（Word版）.docx)。
