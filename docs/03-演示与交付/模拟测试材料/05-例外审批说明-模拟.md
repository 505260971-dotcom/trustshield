# 合同底线例外审批/补件说明（模拟）

## 适用范围

本文件仅用于说明合同底线规则（R03、R04、R05、R16 等）出现例外时需要的审批或补件。它**不能**用于取消、覆盖或放宽 `CREDIT_*` 信审阻断；后者必须回到客户信审，形成新的已生效版本后重新复审合同。

## 风险合同中需要处理的事项

| 风险项 | 可否在合同侧处理 | 建议处理方式 |
| --- | --- | --- |
| R03：承兑汇票 | 可走例外审批，但本演练优先修订为银行转账 | 如保留，须集团财务总监书面审批；同时还要先修改信审版本，将 `acceptance_bill` 纳入允许付款方式。 |
| R04：连带责任 | 可走例外审批，但本演练优先删除 | 如保留，须集团财务总监书面审批。 |
| R05：排他/独家 | 可走例外审批，但本演练优先删除 | 如保留，须集团财务总监书面审批。 |
| R16：VMI/JIT | 可走例外审批，但本演练优先删除 | 如保留，须财务审批主管书面审批；同时还要先修改信审版本允许 VMI/JIT。 |
| R06/R07/R10/R11/R12/R13/R14/R15 | 原则上直接按底线模板修改 | 无法确认的事实应走“待补材料”，而不是输出通过。 |

## 演练补件示例：质保条款

**补件名称：** 质量保证与验收规范（模拟）

**补件说明：** 产品质保期为自每批交付并验收合格之日起 24 个月或累计 300,000 啤次，以先到者为准；替换品不重新起算质保期，除非双方另行书面约定。

**预期系统动作：** 如风险合同被识别为 R07（质保口径不全），在案件“待补材料”中上传或记录该说明，再在修订合同中写入完整条款并复审。

## 关键禁止事项

1. 不能用集团财务总监/财务审批主管的合同例外审批，直接覆盖 `CREDIT_TERM`、`CREDIT_PREPAYMENT`、`CREDIT_PAYMENT_METHOD`、`CREDIT_DELIVERY_MODE`、`CREDIT_EXPOSURE` 或 `CREDIT_OVERDUE_LOCK`。
2. 不能在旧信审 V1 生效后把合同改成更长账期、更低预付款、更高总敞口或新增 VMI/JIT，并仍以 V1 导出可签约建议稿。
3. 如必须放宽商业条件，应新建信审 V2、重新上传/核验材料和敞口、完成两级审批，再重新提交合同审查。
