# 从信审到合同审核：完整演练操作手册

本手册以 `README.md` 指定的虚构客户和材料为例。正常演练约 20–30 分钟；若生产 Agent 未配置，可按“异常分支 A”验证系统的失败关闭和人工留痕路径。它是逐步操作脚本，不是自动化代办清单：每个会改变业务状态的动作均由操作人明确确认后再执行。

## 演练方式：操作人主导、Agent 陪跑

1. 先阅读 [00-实跑前清理与协作规则.md](./00-实跑前清理与协作规则.md)，完成本地数据重置与账号准备。
2. Agent 只在当前步骤协助启动服务、定位页面、解释字段、读取材料和核对页面结果；不会预建案例、代为审批、代为修改或导出。
3. 标有 **停点** 的位置必须由操作人检查页面结果并明确决定“继续”或“停止/排查”。即使材料给出示例审批意见，是否提交、是否批准和如何处置风险仍由操作人决定。

## -1. 空库前置准备

1. 使用管理员账户登录，进入 **组织与规则 → 团队成员**（名称可随前端版本略有不同）。从干净数据库启动时，只会有初始管理员；“系统设置”用于模型与运行配置，不用于创建成员。
2. 创建以下演练账号：`reviewer`、`director`；如要以业务端发起合同，再创建 `business`。为每个账号设置仅用于本地演练的独立密码，密码不写入材料包或截图。
3. 以各账号分别登录一次，确认角色分别具有“信审管理”“信审审批”“合同发起”的入口；随后退出，回到 `reviewer`。

**停点 A：** 确认数据库中没有既有信审、合同、审批、审计、上传或导出记录，并且三个演练角色均可登录。完成后才开始第 1 步。

## 0. 先理解流程与职责边界

```text
业务申请/CRM
  → 信用审核专员收集材料、保存敞口、运行量化评估
  → 审核专员确认/修订报送依据
  → 财务审批主管复核
  → 集团财务总监最终批核
  → 已生效信审版本
  → 业务发起合同审查并强制绑定该版本
  → AI/规则审查 + 人工处置 + 例外审批/补件
  → 复审通过后导出建议稿、推送 OA、留存审计记录
```

信审决定“能不能与该客户在什么商业边界内交易”；合同审查决定“合同文本是否触碰公司底线、是否有证据和例外审批”。前者不能被后者覆盖。

本演练中，信审版本的业务类型填 `TKP`（注塑组件制造）；进入合同审查时选择“模塑一体”，是为了覆盖该合同规则库中特有的 R15/R16（价格、VMI/JIT）检查。二者分别服务于信审模型和合同规则路由，不表示合同绑定的客户或信审版本发生变化。

## 1. 创建客户信审 V1

1. 用信用审核专员（或管理员）登录，进入 **客户信审**。
2. 点击 **新建信审版本**，按照 [01-信审申请单.md](./01-信审申请单.md) 的“初始申请条件”填写：
   - 客户：远辰汽车零部件（模拟）有限公司；业务类型：`TKP`；
   - CNY 1,000,000；45 天；30%；仅银行转账；不允许 VMI/JIT。
3. 保存后打开该信审详情。此时状态应为“草稿”。
4. 在“材料与交易敞口”中，选择“财务报告”，上传 [02-客户财务报告-模拟.docx](./02-客户财务报告-模拟.docx)。确认文字资产已保存。
5. 根据 [03-CRM-ERP敞口快照-模拟.docx](./03-CRM-ERP敞口快照-模拟.docx)，在 CRM/ERP 敞口快照填写：已出货未收款 100,000、已入单 200,000、逾期金额 0、最长逾期 0、币种 CNY，点击保存快照。

**停点 B：** 操作人确认草稿的客户、条件、材料解析状态和敞口快照均与材料一致，再运行量化评估。

### 你应该检查什么

- 货币必须都为 CNY，否则模型会以“币种口径不一致”阻断自动建议。
- 逾期天数必须为 0；超过 30 天会触发逾期锁定，不能进入正常授信流程。
- 信审材料不是合同附件的替代品；它们只服务于信用评估和证据留痕。

## 2. 运行量化信审并形成可送审版本

1. 点击 **运行量化评估**。
2. 在生产环境中，依次查看 Agent 的证据读取、核验 Claims、评分卡、风险/补件和建议条件；核心事实覆盖率应为 100%。
3. 若结果显示“可应用建议”，点击 **应用建议到草稿**；若结果不适用，使用“审核专员确认与修订”填入标准授信边界，并粘贴 `01-信审申请单.md` 的人工复核依据。
4. 点击 **送主管复核**。

**停点 C：** 操作人查看评估运行态、证据/Claims、评分卡和审核专员留痕后，决定是否送主管；Agent 不得替代该决定。

### 异常分支 A：未配置生产 Agent / 评估失败

系统设计为失败关闭：不能因为只有文本样本就自动形成可审批额度。此时不要伪造“通过”。应：

1. 查看 Agent 的“待补材料/运行态”；核对 LLM、重排服务、安全运行环境和材料解析状态。
2. 如具备真实人工核验授权，仍可通过“审核专员确认与修订”提交带理由的人工报送依据；该理由应说明来源、期间、币种、敞口和风险判断。
3. 继续执行后续审批。没有审核专员确认/修订依据的草稿不能送主管。

## 3. 完成两级信审审批，取得已生效版本

1. 切换到 **财务审批主管** 账号，打开 V1，点击 **复核通过**，填写 `01-信审申请单.md` 的主管意见。
2. 状态应变为“待最终批核”（`pending_final`）。
3. 切换到 **集团财务总监** 账号，点击 **最终批核**，填写最终批核意见。
4. 验证状态为“已生效”（`approved`）。

**停点 D：** 由操作人确认这确为需要生效的 V1，并分别以 `director` 和 `admin` 完成其本人应做的审批；不要由同一人用不同账号代替业务审批结论。

此时才进入合同环节。不要在合同页面手工编造客户、额度或账期；发起合同评审时只能从已生效信审版本中选择。

## 4. 发起风险合同审查，观察“信审阻断”

1. 以有合同发起权限的账号进入 **发起合同评审**（或案件中心）。
2. 上传 [04-风险合同-待审.docx](./04-风险合同-待审.docx)。
3. 合同审查的业务类型选择 **模塑一体**（用于触发该专项合同规则，和信审中的 `TKP` 是不同维度）；客户选择“远辰汽车零部件（模拟）有限公司”；绑定刚刚已生效的信审 V1。
4. 提交，等待“解析 → 本地脱敏 → 字段抽取 → 规则候选 → 语义研判 → 确定性规则/信审边界校验 → 汇总”。
5. 打开报告的“原文风险标注”，逐条查看证据和修改建议。

**停点 E：** 操作人确认本次提交绑定的客户、V1 和合同文件无误，再等待审查完成；不要让 Agent 自动触发提交、忽略或导出。

### 必须出现的控制效果

- `CREDIT_TERM`：合同为 60 天（且另有 120 天底线风险），超过 V1 的 45 天。
- `CREDIT_PREPAYMENT`：合同预付款 20%，低于 V1 的 30%。
- `CREDIT_PAYMENT_METHOD`：合同有银行承兑汇票，V1 只允许银行转账。
- `CREDIT_DELIVERY_MODE`：合同有 VMI，V1 禁止。
- `CREDIT_EXPOSURE`：800,000 合同额 + 300,000 既有敞口 = 1,100,000，超过 V1 上限。

总体结论应是“信审阻断”。尝试忽略任一 `CREDIT_*` 发现，系统应拒绝；尝试导出修订建议稿/双语稿也应拒绝。

## 5. 区分两类问题，正确处置

### A. 合同文本自身的底线风险

例如 R03 承兑汇票、R04 连带责任、R05 排他、R06 无责取消、R07/R08 质保、R09 法律识别、R10 赔偿、R11 期限、R12 间接损失、R13 关联方外溢、R14 知识产权、R15 价格、R16 VMI。优先按风险建议直接改合同；确需例外时，按规则所列角色发起审批/补件。参考 [05-例外审批说明-模拟.md](./05-例外审批说明-模拟.md)。

### B. 信审边界越界

`CREDIT_*` 不是合同例外审批能解决的事项。本演练优先将合同改回 V1 边界。如果业务确需把 45 天改为 60 天、允许承兑汇票或 VMI/JIT、降低预付款或把总敞口提高到 1,100,000 以上，则必须：

1. 新建或更新信审 V2；
2. 重跑材料与敞口核验；
3. 重新由主管与集团财务总监审批；
4. 用已生效 V2 重新提交合同审查。

## 6. 用修订合同复审，完成可签约闭环

1. 将 [06-修订后合同-复审.docx](./06-修订后合同-复审.docx) 提交为新版本或增量复审，仍绑定 V1。
2. 核对：合同总价 CNY 600,000，叠加既有敞口为 CNY 900,000；45 天账期；30% 交付前收款；银行转账；无 VMI/JIT。
3. 所有 `CREDIT_*` 应消失。若系统给出需要人工确认的合同规则，打开原文证据逐一核对、采纳修改/关闭并完成所需审批或补件。
4. 完成后可导出：
   - **修订建议稿**：仅带人工明确采纳/编辑/批准的建议；
   - **原文版**：用于留档对照；
   - **双语对照稿**：先完成翻译，再导出。
5. 可选：推送 OA Mock，依次以信用审核专员、财务审批主管、集团财务总监角色提交意见；在案件、审批、导出和审计日志中留痕。

**停点 F：** 在每项 `CREDIT_*` 已消失、合同底线事项已由操作人核对、且必要审批都真实完成前，不导出任何可签约建议稿。

## 7. 最终验收

按 [07-预期结果与验收清单.md](./07-预期结果与验收清单.md) 完成逐项勾验。尤其确认以下两条硬规则：

1. 合同端绝不允许忽略 `CREDIT_*`；
2. 信审 V2 一旦生效，基于 V1 的合同不得继续导出可签约建议稿，必须重新审查。
