## 二、首版合同 `04-首版销售合同-风险.docx`

合同业务类型选择“模塑一体”，绑定启明智造 V1 后，预期至少出现以下信审阻断：

| 规则 | 触发事实 | 预期结论 |
| --- | --- | --- |
| `CREDIT_TERM` | 交付后120天付款 | 120 > V1 的60天上限，合同端不能豁免。 |
| `CREDIT_PREPAYMENT` | 交付前25%收款 | 25% < V1 的40%下限，合同端不能豁免。 |
| `CREDIT_PAYMENT_METHOD` | 银行承兑汇票/商业承兑汇票 | V1 只允许银行转账。 |
| `CREDIT_DELIVERY_MODE` | VMI/JIT、供应商管理库存 | V1 禁止 VMI/JIT。 |
| `CREDIT_EXPOSURE` | 合同1,200,000 + 既有敞口800,000 | 总敞口2,000,000 > V1 上限1,800,000。 |

首版合同还应被识别出若干合同底线风险，包括付款比例、超长账期、承兑、连带责任、排他、无责取消、质保、法律识别、赔偿、期限、知识产权、关联方外溢、价格锁定和 VMI/JIT。具体命中数量可能受模型配置、候选召回和人工确认影响，但不能跳过原文证据核对。

**首版合同不通过标准：**

- 报告总体结论不能作为可签约结论；
- `CREDIT_*` 不能被忽略、采纳或通过合同审批覆盖；
- 不应导出可签约的修订建议稿或双语稿；
- 案件应进入审核专员处理、补件或业务修订路径。

## 五、最终闭环

只有同时满足以下条件，才可以进入签约/归档：

1. 当前使用的信用版本为客户已生效信审；
2. V3 最终合同版本没有 `CREDIT_*` 信审阻断；若业务金额必须高于 CNY 460,000，才改走重新信审和新案件绑定；
3. 合同底线风险已经采纳、编辑、关闭或完成对应审批；
4. 待补材料和案件待办已经关闭；
5. 当前角色具有对应的案件流转权限；
6. 导出文件、版本对比、审批和归档记录均有审计留痕。

## 六、异常路径验收

| 异常 | 正确行为 |
| --- | --- |
| 财报解析失败或模型未配置 | 显示失败关闭，不产生伪造评分或授信建议；可在有授权和充分依据时走人工兜底。 |
| 信审没有 `approved` 版本 | 合同发起页不能进入正式审查，案件门禁显示“信审前置条件未完成”。 |
| 首版合同尝试忽略 `CREDIT_*` | 系统拒绝合同端处置，提示先更新信审并重新复审。 |
| 修订后仍有 `CREDIT_*` | 不能导出修订建议稿，继续停留在合同修订/信审变更路径。 |
| Agent 建议额度低于修订合同总敞口 | 保留原合同审查记录，创建新的信用审核版本；新版本审批完成后重新创建并绑定合同案件。 |
| 审批或补件未闭环 | 案件不能确认可签约或归档。 |
