# 启明智造场景：演练边界与角色分工

## 1. 演练目标

本材料包不是为了演示“模型给出一个分数”，而是为了验证以下业务控制：

1. 客户信用条件先经过信审和审批，才可以被合同消费；
2. 合同金额必须与客户既有敞口合并判断；
3. 合同不能通过例外审批绕过客户级账期、预付款、付款方式和交付模式边界；
4. 合同修订后必须形成新的当前版本并重新审查；
5. 每一次人工确认、审批、补件和导出都要能回溯到责任角色。

## 2. 角色分工

| 角色 | 可以做什么 | 本场景的责任 |
| --- | --- | --- |
| `admin` | 创建账号；最终信审审批；集团级合同审批；查看组织、规则和审计 | 初始化演练环境；在审批路由要求时完成终审 |
| `reviewer` | 创建/修改信审草稿；上传财报和信审材料；录入敞口；运行评估；确认或修订 Agent 建议；处理合同风险 | 完成 V1 信审；识别首版合同的阻断；确认修订后可否推进 |
| `director` | 主管级信审复核；主管级合同审批、退回或上报 | 复核 V1 商业边界，并对合同流程作出主管决定 |
| `business` | 发起合同申请；上传主合同、补件和修订版；查看本人案件 | 提交首版风险合同并按意见上传修订版 |

## 3. 操作人主导原则

- Agent 只负责读取受控材料、抽取事实、提出建议和记录运行链路。
- 创建信审、上传材料、运行评估、确认 Agent 建议、送审、批准、处置风险、导出和归档都必须由操作人确认后执行。
- 不使用数据库直接改状态，不用浏览器开发者工具改金额、额度或案件阶段。
- 不把“Agent 未配置”“评估失败”“没有形成评分”解释成授信通过。
- 不用主管或最终审批人的合同例外审批去覆盖 `CREDIT_*`。

## 4. 演练停点

| 停点 | 操作人必须确认的内容 |
| --- | --- |
| A：信审草稿 | 客户、业务类型、币种、额度、账期、预付款、付款方式和 VMI/JIT 开关。 |
| B：信审证据 | 财报文字资产、7 项核心财务事实、既有敞口 CNY 800,000、逾期 0 天。 |
| C：信审报送 | Agent 建议是否可采用；若人工修订，理由是否说明了来源和边界。 |
| D：信审生效 | V1 是否真的变成“已生效”，审批意见和路由原因是否留痕。 |
| E：首版合同 | 至少五项 `CREDIT_*` 是否被识别；首版合同不能走可签约或修订建议导出。 |
| F：V2 二次阻断 | 合同金额 CNY 1,000,000 + 既有敞口 CNY 800,000 = CNY 1,800,000；确认其仍被当前 CNY 1,260,000 信审边界阻断。 |
| G：V3 通过复审 | 合同金额 CNY 450,000 + 既有敞口 CNY 800,000 = CNY 1,250,000；确认无 `CREDIT_*`，再关闭普通风险/材料待办。 |
| H：归档 | 合同风险、审批、导出和归档是否都有记录。 |

## 5. 开始前的安全检查

1. 确认材料包和当前数据库中的其他场景没有混用；本场景客户名必须完整使用“启明智造（模拟）有限公司”。
2. 如果不清空数据库，不要删除其他人的历史案件；只要使用新客户名即可与旧场景隔离。
3. 上传信审财报时只上传 `02-客户财务报告-启明智造.docx`；上传 DOCX 后不要再把同一内容重复作为另一份财报。
4. `03-CRM-ERP敞口快照-启明智造.docx` 是录入参考，不要把它当成信审财报上传。
5. 合同首审使用 `04-首版销售合同-风险.docx`，V2 二次阻断使用 `06-修订销售合同-复审.docx`，最终通过复审使用 `11-最终销售合同-可签约V3.docx`。
