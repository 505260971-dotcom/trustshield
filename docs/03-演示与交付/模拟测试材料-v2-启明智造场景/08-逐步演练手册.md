# 启明智造场景：逐步演练手册

> 适用版本：当前仓库前端与后端实现。所有金额、客户和意见均为模拟数据。

## 1. 建议的演练顺序

不要一开始就上传合同。按下面顺序演练，才能验证信审和合同之间的前置关系：

```text
环境与账号
  → reviewer 创建信审 V1
  → reviewer 上传财报与敞口并运行评估
  → reviewer 固化 Agent/人工报送依据
  → director 主管复核
  → admin 最终批核
  → business 发起合同并绑定 V1
  → business 上传首版风险合同
  → reviewer 处理阻断并要求修订
  → business 上传修订合同 V2
  → reviewer 复核、处置合同风险
  → director/admin 按门禁审批
  → reviewer 归档
```

## 2. 启动前准备

### 2.1 服务与账号

在仓库根目录启动当前开发服务：

```powershell
.\dev.ps1
```

浏览器访问：

```text
http://127.0.0.1:5173
```

由 `admin` 在 **组织与规则** 创建 `reviewer`、`director`、`business` 三个演练账号。不要把密码写入本材料，也不要让同一个人用一个账号代替其他角色的审批记录。

### 2.2 数据隔离

- 如果当前数据库有旧场景数据，不要直接删除；本场景使用新的客户名“启明智造（模拟）有限公司”即可隔离。
- 如果要求严格从空库复现，请先阅读旧材料目录中的 `00-实跑前清理与协作规则.md`，只清理明确允许清理的数据库、WAL/SHM 和上传件。
- 不要删除规则目录、模型配置、tessdata 或本材料目录。

## 3. 第一步：reviewer 创建信审 V1

1. 以 `reviewer` 登录。
2. 打开左侧 **客户信审**，点击 **新建信审版本**。
3. 根据 `01-信审申请单-启明智造.md` 填写：
   - 客户名称：`启明智造（模拟）有限公司`；
   - 业务类型：`TKM`；
   - 币种：`CNY`；
   - 最大信用额度：`1800000`；
   - 最长账期：`60` 天；
   - 交付前最低收款：`40`%；
   - 付款方式：仅选择“银行转账”；
   - VMI/JIT：不允许；
   - 申请说明：粘贴申请单第 3 节。
4. 点击 **保存评估草稿**。
5. 在信审列表确认客户出现 V1，状态为待评估或草稿。

**停点 A：** 操作人确认客户、版本和所有条件都属于启明智造场景，不要把旧“远辰汽车”的金额复制进来。

## 4. 第二步：上传财报和 CRM/ERP 敞口

1. 打开启明智造 V1 详情，进入“材料与交易敞口”。
2. 文档类型选择 **客户财报**。
3. 上传 `02-客户财务报告-启明智造.docx`。
4. 等待材料状态显示“文字资产已保存”或可核验文字。
5. 在 CRM/ERP 敞口快照中填写：

| 字段 | 值 |
| --- | ---: |
| 当前应收 | `350000` |
| 已入单金额 | `450000` |
| 逾期金额 | `0` |
| 最长逾期天数 | `0` |
| 币种 | `CNY` |

这些数值也记录在 `03-CRM-ERP敞口快照-启明智造.docx` 中，但 DOCX 文件本身是录入参考，不是直接上传材料。

**停点 B：** 最近快照应显示既有敞口 CNY 800,000。若把 350,000 或 450,000 填错，后面的 `CREDIT_EXPOSURE` 预期会改变。

## 5. 第三步：运行量化评估并固化报送依据

1. 点击 **运行量化评估**。
2. 等待 Agent 运行结束，查看评分卡、已核验 Claims、来源证据、缺失材料和风险标记。
3. 如果生产 Agent 已就绪、形成完整事实并给出适合本场景的建议，可以点击 **应用建议到草稿**。
4. 如果建议与本场景的标准边界不同，打开“审核专员确认与修订”，输入 `01-信审申请单-启明智造.md` 第 4 节的人工依据，并保存人工确认/修订。
5. 如果模型未配置、超时或评估失败：
   - 保留失败记录和失败原因；
   - 不把失败结果当作自动通过；
   - 只有在有人工授权、已核对财报和敞口后，才填写人工兜底依据；
   - 页面应显示 `manual_override` 或相应人工报送模式。
6. 确认列表中的信审版本已经显示审核依据后，点击 **送主管复核**。

**停点 C：** 记录本次评估是 Agent 建议、审核专员修订还是人工兜底，并确认人工理由已经写入案件。

## 6. 第四步：主管和最终审批

### 6.1 director 主管复核

1. 退出 `reviewer`，以 `director` 登录。
2. 打开 **客户信审**，找到启明智造 V1。
3. 核对：客户、额度、账期、预付款、付款方式、VMI/JIT、财报证据和既有敞口。
4. 点击 **复核通过**，填写：

   > 已复核启明智造财报、7项核心财务事实、CRM/ERP既有敞口和审核专员报送条件，同意 V1 采用 CNY 1,800,000 总敞口、60天账期、40%交付前收款、仅银行转账且不允许 VMI/JIT 的边界。

5. 由于本场景账期达到 60 天、预付款不高于最终审批阈值，通常会进入最终审批；以页面路由快照为准。

### 6.2 admin 最终批核

1. 退出 `director`，以 `admin` 登录。
2. 打开 **客户信审**，找到启明智造 V1。
3. 核对主管意见和路由原因。
4. 点击 **最终批核**，填写：

   > 同意启明智造（模拟）有限公司 V1 客户信用边界。合同端不得超过 60 天账期、40%交付前收款、CNY 1,800,000 总敞口和仅银行转账的商业条件；如需 VMI/JIT，必须重新申请信审。

5. 确认状态变为 **已生效**。

**停点 D：** 只有看到“已生效”后才继续合同演练；不要通过复制条件或手工修改 URL 跳过信审绑定。

## 7. 第五步：business 发起首版风险合同

1. 退出 `admin`，以 `business` 登录。
2. 打开 **发起合同审查**。
3. 选择或填写客户：`启明智造（模拟）有限公司`。
4. 在信审选择框中选择已生效 V1。
5. 合同业务类型选择 **模塑一体**，这是为了让合同规则同时检查模具交付、账期和 VMI/JIT 条款；信审业务类型仍然是 `TKM`。
6. 申请说明可填写：

   > 验证启明智造客户信用边界与模塑一体合同底线联动，首版合同故意保留风险条款，后续根据审查结果修订。

7. 上传 `04-首版销售合同-风险.docx` 作为主合同。
8. 点击 **创建案件并提交审查**。
9. 等待案件从“系统审查中”进入“审核员人工复核”。

## 8. 第六步：reviewer 处理首版合同阻断

1. 退出 `business`，以 `reviewer` 登录。
2. 打开 **合同案件**，进入启明智造案件。
3. 先看案件顶部的 **当前版本通关检查**，应看到：
   - 信审边界：存在阻断；
   - 合同风险处置：有待处理风险；
   - 待补材料：视 Agent 识别结果而定；
   - 条款例外审批：视风险规则而定。
4. 打开当前版本审查报告，重点确认：
   - `CREDIT_TERM`：120 天超过 60 天；
   - `CREDIT_PREPAYMENT`：25%低于40%；
   - `CREDIT_PAYMENT_METHOD`：出现承兑汇票；
   - `CREDIT_DELIVERY_MODE`：出现 VMI/JIT；
   - `CREDIT_EXPOSURE`：1,200,000 + 800,000 = 2,000,000，超过1,800,000。
5. 对 `CREDIT_*` 不点击忽略或采纳；报告应提示“先更新信审后复审”。
6. 对合同底线风险，根据 `05-条款补件与例外说明-启明智造.md` 选择修订或创建补件要求。
7. 退回业务补件，说明：

   > 请按启明智造场景材料修订合同金额、账期、预付款、付款方式、VMI/JIT、质保、责任、期限和知识产权条款。客户信审阻断不能在合同端通过例外审批放行。

**停点 E：** 首版合同保持阻断状态，不能确认可签约，也不要导出修订建议稿作为最终合同。

## 9. 第七步：business 上传修订合同 V2

1. 退出 `reviewer`，以 `business` 登录。
2. 打开 **合同案件**，进入启明智造案件。
3. 点击 **上传修订合同** 或案件中的修订上传按钮。
4. 上传 `06-修订销售合同-复审.docx`。
5. 等待 V2 审查完成。

修订稿应满足：

- 合同金额 CNY 1,000,000；
- 交付前收款 60%；
- 余款交付后 60 天内银行转账；
- 不采用 VMI/JIT；
- 合同有效期三年；
- 质保为24个月或300,000啤次先到者；
- 责任和知识产权条款不再向客户或关联主体无限外溢。

## 10. 第八步：reviewer 复审 V2、版本对比和后续审批

1. 以 `reviewer` 登录，打开启明智造案件。
2. 打开 V2 报告，确认 `CREDIT_*` 不再出现。
3. 进入 **版本对比**，选择首版 V1 和当前 V2，点击 **开始对比**。
4. 核对新增风险、消除风险、持续风险和变更条款。
5. 逐条处理仍然存在的合同底线风险；如果某条属于例外，按审批层级提交；不能直接用“无风险”替代原文证据。
6. 待风险、补件和条款审批门禁关闭后，根据当前案件阶段选择：
   - **确认可签约**；
   - **提交主管审批**；
   - **退回业务补件**。
7. 若进入主管审批，以 `director` 登录处理；若路由上报最终审批，再以 `admin` 登录处理。
8. 进入“可签约”后，由 `reviewer` 或系统允许的责任角色确认签署并归档。

## 11. 第九步：导出和验收

只有 V2 没有 `CREDIT_*`、合同风险和审批门禁已闭环后，才演示：

- 导出修订建议稿；
- 导出原文版留档；
- 导出双语对照稿；
- 查看版本对比；
- 查看案件流程记录；
- 查看管理员审计日志。

如果导出被拒绝，优先检查当前绑定信审是否仍为启明智造已生效 V1、是否还有信审阻断、是否有未完成补件或条款审批，不要绕过导出门禁。
